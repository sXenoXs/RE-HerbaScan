# Acceptance Testing Plan — HerbaScan v0.9.3

**Testing Type:** Functional — Acceptance (User Acceptance Testing / Thesis Validation)  
**Scope:** Real-world user scenarios aligned with DOH requirements, PITAHC use cases, and undergraduate thesis objectives  
**Date:** March 7, 2026  
**Version:** v0.9.3

---

## Overview

Acceptance tests validate HerbaScan against its core thesis and business requirements: accurately identifying Philippine medicinal plants for rural communities, providing safe and trustworthy herbal information, and meeting academic standards for explainable AI and multilingual support. These tests are conducted with real end-users (PITAHC staff, community health workers, or fellow students) in realistic scenarios.

---

## Test Cases

| Test Case Scenario ID | Name of the Module / Function | Test Case Scenario | Action | Actual Input | Pass | Fail | Comments / Suggestions |
|---|---|---|---|---|---|---|---|
| AT-001 | DOH-approved plants identification accuracy | Verify that all 10 official DOH-approved medicinal plants are correctly identified by the CNN model with a top-1 confidence score ≥ 60% when a clear, well-lit leaf photo is presented | For each of the 10 DOH plants (Lagundi, Sambong, Akapulko, Ampalaya, Bawang, Bayabas, Niyog-niyogan, Tsaang Gubat, Ulasimang-bato, Yerba Buena): scan a real or high-quality printed leaf photo under good lighting and record the top-1 result and confidence | 10 clear leaf photos (one per DOH plant), natural daylight, no background clutter | | | Pass criteria: top-1 prediction matches the correct plant for all 10; confidence ≥ 60% for each. Record actual confidence per plant for thesis data. |
| AT-002 | Rural offline field use — no connectivity | Verify that a user in a location with no mobile data and no Wi-Fi can complete the full scan flow (offline TFLite) and see a meaningful result (plant name, heatmap, XAI explanation, safety information) without any "network error" screen | Enable airplane mode; perform scans for 5 different plants from the 42-plant database; observe results | 5 leaf photos; airplane mode active; no SIM card or Wi-Fi | | | Pass criteria: all 5 scans complete without a network error message; each shows a plant name, CAM heatmap, at least one XAI section, and at least one safety card. Simulates rural barangay health center scenario. |
| AT-003 | Poor lighting scan — graceful degradation | Verify that when a photo is taken in near-dark or very dim conditions, the app displays the "Poor Image Quality" screen with 6 scanning tips rather than confidently showing a wrong plant identification | In a dimly lit room, capture a photo of any plant using the scan screen | Leaf photo taken under < 10 lux artificial light (e.g. a single dim bulb 2 meters away) | | | Pass criteria: app shows "Poor Image Quality" screen (not PlantResultScreen with a confident wrong label); 6 scanning tips are visible; user can tap "Retake Photo" to restart. |
| AT-004 | Multilingual use — full Filipino experience | Verify that switching the app language to Filipino results in all UI elements — navigation labels, screen titles, error messages, preparation instructions, and safety warnings — appearing in Filipino; no English text leakage | (1) Launch app; (2) Settings → Language → Filipino; (3) Browse all main screens (Home, Scan, Browse, History, Settings, Plant Detail, Preparation Guide); (4) Trigger an error (e.g. scan in airplane mode) to see error messages | No external input; language preference set to Filipino | | | Pass criteria: no hardcoded English strings visible; all labeled elements use `AppLocalizations.of(context)` with Filipino translation; preparation guide steps appear in Filipino. |
| AT-005 | Safety-critical plant — Tuba-tuba (toxic) | Verify that scanning Tuba-tuba (Jatropha curcas) correctly surfaces the toxic classification: red "NOT RECOMMENDED" badge, `strict_contraindications` populated with "Seeds toxic – Curcin; sap irritant", and no Preparation Guide link since Tuba-tuba has zero preparation methods | Scan or present a Tuba-tuba leaf photo; navigate to Safety tab; attempt to open any preparation method | Real or printed Tuba-tuba leaf photo | | | Pass criteria: top-1 result shows "Tuba-tuba"; Safety tab shows a red card with toxicity information; Medicinal tab shows no "Preparation Guide" card; user cannot accidentally start a preparation for this toxic plant. |
| AT-006 | User feedback data collection for thesis research | Verify that the feedback data collection pipeline works end-to-end: complete a scan → navigate to Feedback screen → submit a 5-star rating with category "Accuracy" and a comment → data saved to local JSON storage → JSON file is exportable and contains all submitted fields | (1) Complete any plant scan; (2) Open Settings → Feedback; (3) Submit 5-star rating, category "Accuracy", comment "Correctly identified Lagundi."; (4) Export data from Performance Dashboard | Any completed scan; test user comment text | | | Pass criteria: feedback JSON contains `{ rating: 5, category: "Accuracy", comment: "Correctly identified Lagundi." }`; export function produces a valid JSON file; no data loss between submission and export. |
| AT-007 | 6-digit OTP password reset — bulletproof flow | Verify that a user who forgot their password can reset it using the 6-digit OTP code from the Supabase email (not a link), set a new password, and sign in successfully with the new password | (1) On Login screen, tap "Forgot password?"; (2) Enter registered email; (3) Receive reset email; (4) Enter 6-digit code in "Enter the code from your email" screen; (5) Set new password (meets all 5 requirements); (6) Sign in with new password | Registered test email; valid 6-digit code from email | | | Pass criteria: OTP verification succeeds; new password accepted; sign-in with new password returns `isLoggedIn = true`. Verify that this flow works even if the link in the email is pre-fetched by a mail scanner (link pre-fetch does not invalidate the code). |
| AT-008 | XAI explanation — thesis defensibility (no live LLM) | Verify that all 42 plant explanations come from the deterministic offline JSON (`plant_explanations.json`) and no live network call is made to any generative AI service during explanation generation, supporting the thesis claim of a no-LLM-at-runtime system | (1) Enable airplane mode; (2) Perform scans for 5 different plants; (3) Open Summary tab for each; (4) Monitor network monitor (Android Studio Network Profiler or `flutter run --verbose`) for any outbound HTTP to Gemini, OpenAI, or similar endpoints | 5 different plant scans; airplane mode enabled; network profiler active | | | Pass criteria: zero HTTP calls to any AI API endpoint; all Summary tab content is populated correctly from `plant_explanations.json`; network profiler shows only SQLite and local asset reads. |
| AT-009 | Admin can deactivate a user account | Verify that an admin can set `is_active = false` for a regular user via User Management, and that when that user next opens the app they are signed out with the message "Your account has been deactivated by an administrator." | (1) Admin signs in on one device; (2) Admin Portal → User Management → find test user → Deactivate; (3) On the test user's device, open the app or wait for next role refresh; (4) Observe alert | Admin account and test user account (two devices or test flow) | | | Pass criteria: test user device shows `AlertDialog` with deactivation message; tapping OK navigates to `/login`; test user cannot sign back in until admin reactivates (`is_active = true`). |

## Notes

- Acceptance tests are the final gate before thesis submission and Google Play Store preparation.
- Conduct AT-001, AT-002, AT-003, and AT-004 with external testers (PITAHC staff or community members) to collect authentic usability and accuracy data.
- Record all results in the thesis research data collection sheet for quantitative analysis.
- AT-006 data (feedback JSON) will be used as primary research data for the thesis survey chapter.
