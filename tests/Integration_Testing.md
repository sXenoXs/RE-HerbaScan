# Integration Testing Plan — HerbaScan v0.9.3

**Testing Type:** Functional — Integration  
**Scope:** Two or more connected components (service + provider, provider + DB, Flutter → Supabase, Flutter → Railway)  
**Date:** March 7, 2026  
**Version:** v0.9.3

---

## Overview

Integration tests verify that HerbaScan's connected layers work correctly together. Unlike unit tests, dependencies are not mocked — real (or real-ish staging) instances of SQLite, Supabase, and the Railway backend are used where feasible. The focus is on data passing correctly between boundaries: service to provider, provider to DB, Flutter to cloud.

## Notes

- Integration tests require a live Supabase project (`tsahfzmxqsgbxrrtbdnw`) and a warm Railway instance, or use CI environment variables pointing to staging credentials.
- Run with: `flutter test test/integration/` (using `integration_test` package or custom test runner).
- Clean up test data (test user accounts, test scan rows) after each run to keep staging clean.
